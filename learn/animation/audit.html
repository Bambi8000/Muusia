A survey of movement in Muusia: loops you can try with existing controls, and ideas for giving each node its own motion. Birds can fly, ribbon folds can travel, and water can carry waves.

A first physical test

Grid → Wave, 24 frames, one pen, two sheets of 4 × 3 frames. Its loop join is easy to inspect, there are few lines to draw, and alignment errors are visible.

Try 48-frame Murmuration or Plaid next. Iris and Organic Ribbon make richer second tests, with more pen-down distance.

For downloadable projects, start with the six animation examples or Grid Hairs + Solids.

What was checked

The study covers all 310 built-in definitions in the reviewed snapshot, including four hidden definitions. Their controls and animation-relevant implementation were reviewed.

Eight recipes were also calculated using real nodes at 24 and 48 frames. Suggestions for the other nodes are design assessments. This is not a claim that every node has a finished seamless animation mode, a browser export test or a physical plotting test.

01 / shared time

A loop needs the right final frame.

Calculate frames at moments 0 … N−1. The last saved frame should not duplicate the first: the movement between them is the final step of the loop. The virtual moment N should match moment 0.

u = i / N
w = ½ − ½ cos(2πu)

u travels once around a phase. w moves smoothly out and back. For a range a…b, use a + (b−a)w. Matching endpoints alone does not guarantee smooth speed or stable lines.

24 frames at 8 fps make 3 seconds; 48 at 12 fps make 4 seconds. In the reviewed app, Play advances about every 170 ms. This is separate from the final video's frame rate.

Both divisions fit Math's current B range of −100…100. Use rot ° directly for angles in degrees, or u × 2π for radians. Frame also provides wave loop for breathing motion.

Frame · t uses i/(N−1) and includes both endpoints. That is useful for a one-time reveal, but can add a repeated pause in a loop.

Keep the world stable. Fix Seed, object and line counts, sampling density, pens and paper size. Use one shared framing area rather than fitting each frame to its own bounds. Even with the same seed, changing size can rebuild a packing or placement; such nodes need persistent objects with motion applied separately.

04 / from drawings to moving images

A small series before a large work.

  1. Fix the composition. Use the same canvas, pens and movement space in every frame. Start with one pen; check the smallest line spacing at the final physical size.
  2. Inspect the loop. Check N−1 → 0, clipping, empty frames, sudden changes in line count and stationary registration marks.
  3. Arrange with Frame Grid. Set Fill → Animate, Total frames to 24 or 48, and Cell scale → Map canvas. Enable Cell frames, Corner dots and Frame numbers; keep Markers on. Clearance leaves room around the alignment marks.
  4. Export the sheets. A 4 × 3 layout gives 2 sheets for 24 frames, or 4 sheets for 48. Set the outer ANIMATE → Frames to 2 or 4, because it now counts sheets. A 3 × 2 layout gives larger pictures: 4 or 8 sheets.
  5. Plot and photograph. Test one sheet first. Photograph from the same angle under even lighting. Align and crop using the marks, preserve the numbering and assemble a looping video at 8 or 12 fps. A complete automatic animation digitisation workflow still needs development.

SVG and G-code

Frame export already creates numbered SVG, DXF or G-code files and bundles multiple files into a ZIP. G-code requires the correct machine profile; SVG goes through the device's own workflow. See the first physical plot tutorial and two-colour SVG workflow.

Travel Sort does not affect SVG or DXF exports. Use Show direction to inspect its route changes. Shorter travel can reduce the time of a G-code job.

Group multicolour work by sheet. Six pens across 48 separate pictures can mean 240 within-picture pen changes. Four sheets, with every mark of a pen drawn in one pass, reduce that count to 20. This excludes fitting the first pen and preparing each new sheet; export and controller software must preserve pen groups.

Machine homing does not replace paper registration. Keep paper fixed throughout all pen passes for a sheet, and add stationary alignment marks after the animation's transformations.

Estimate from a measured test sheet

20 minutes is an editable example, not a machine measurement. Include travel, lifts, pen changes and paper changes in your test time. Photography and video assembly take additional time.

05 / proposed development order

A shared clock, then motion within each node.

These are development proposals from the review, not controls that the Learn pages add to Muusia.

1

Loop controls and dependable export

Add a Loop phase 0–1 output to Frame without changing existing ports, plus 24/48 presets, an 8/12 fps preview and a last-to-first inspection mode.

Ready when: every frame exports once, empty opening frames are supported, preview and batch export share the same machine context, and old patches still work. Resolve this before a long physical batch.

2

Ready-made patches and two test sheets

Start with Grid → Wave, Lissajous and Grid Hairs; then Murmuration, Plaid, Iris, Concrete Poetry and Organic Ribbon. Add Frame Grid versions and individual frame exports.

Ready when: a 24-frame sequence has been physically plotted, photographed and watched as a loop. The newer downloadable gallery supplies seven editable patches including the combined example; a physical test is still outstanding.

3

Periodic motion in node families

Add travelling phases to cloth, water and noise fields; a Fold phase to Ribbon; and individual delays to plants, fish and repeated motifs.

Ready when: u=0 matches u=1, with stable line ordering and randomness. Preserve object identities and cache fixed structure separately from motion.

4

Images, morphs and landscapes

Extend Morph Layers with continuous Phase, Loop/Ping-pong and 24–48 frames beyond its reviewed 12-layer limit. Image, Portrait and Primitive need stable samples or a one-time solution followed by motion. Shan Shui needs persistent landscape layers, a boat and water.

Ready when: corresponding points, framing and object identities survive the whole sequence. Growth simulations need replayable history and a considered return.

Two export issues found in the reviewed snapshot

The reviewed exportAllFrames builds a context with W/H/frameIdx/frameCount but omits the normal preview's machine context. Machine-dependent node output needs preview/batch parity checks.

Frame-export buttons are disabled when the selected current frame is empty. That makes reveals beginning with no lines harder to export. A future fix should assess the sequence, not just the current frame. These are dated findings, not changes made by this study.

Scope and sources

This is an English edition of the 7 October 2026 study. It preserves the reviewed inventory, readiness categories, geometry and measurements. The app and node algorithms were not changed by publishing this study in Learn.

  • Frame, LFO and Math supply the reviewed timing behaviour. Frame Grid, Collect Frames and Morph Layers supply the layout and collection mechanisms.
  • App.jsx supplies preview and batch-export logic. Snapshot fingerprints identify the review; the historical full-file App.jsx hash is not a release gate.
